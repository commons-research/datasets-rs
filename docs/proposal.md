# Proposal: Programmatic Content-Aware Interoperability for Heterogeneous Datasets

## Question

**Can heterogeneous datasets in large public data repositories be automatically and reliably discovered, classified by their actual contents, and indexed for reproducible programmatic search?**

## Insights and Motivation

Large public repositories, known colloquially as *data lakes*, such as Hugging Face and Zenodo make large numbers of datasets available. However availability does not guarantee effective discovery of said dataset or reuse thereof. Search is commonly driven by repository metadata, free-text descriptions, uploader-provided tags, schemas, and file names themselves. These descriptions may be incomplete, inconsistent, or inaccurate with respect to the data actually present. As repositories grow, they risk becoming *data swamps* rather than lakes, where useful datasets may exist, but finding data with a particular scientific content type can require repository-specific searches and manual inspection.

This project investigates whether discovery can be improved by inspecting underlying dataset contents and assigning evidence-backed scientific labels. Rather than only asking whether a dataset description contains the term `SMILES` for example, the system should determine whether candidate fields actually contain values that can be validate das SMILES. The same approach ca later be extended to molecular formulae, mass-spectrometry data, and other scientific content types.

The project is therefore focused on the research task of **content-aware dataset discovery**, where crawling heterogenous repositories in precise manner, with the goal of inspecting supported artifacts, validating their scientific contents, indexing the resulting classifications, and making those classifications reproducibly searchable.

While initially focused on metabolomics and chemistry datasets, the goal is to make this software generic by nature and therefore capable of being applied to any dataset discovery in any scientific field.

Finally, preliminary reviews of Hugging Face and Zenodo, the two initial data lakes of focus for this project, reveals that search results for datasets can vary substantially depending on queries, dataset metadata, and any other relevant search surfaces. This motivates a controlled comparison between repository-native search and classifications derived from actual underlying data.

### Impact on Commons Lab

For the Commons Lab, the initial chemistry and mass-spectrometry labelers provide a direct route to finding new datasets for analysis and benchmarking. The resulting index may also support later software that retrieves compatible datasets and exposes common scientific fields without repeated dataset-specific discovery and parsing logic.

Together these works establish mature approaches to metadata standards, cross-repository search, domain harmonization, and dataset transformation. The proposed gap lies between metaedata-level discovery and full dataset-specific ETL, automatically inspecting repository contents to determine what scientifically meaningful data are actually present, indexing those results reproducibly, and using verified field locations as the basis for later interoperable access.

## Expected Results

The expected engineering result is a modular system organized around three layers, one for the core functionality used for evaluating the datasets, the crawler itself for crawling resources live from the data lakes, and eventually a server that allows for querying indexed datasets with relevant filters.

Three principal outputs are expected:

1. **Scientific results:** measurements of classification accuracy, generalization, reproducibility, crawler robustness, and inspection cost.
2. **Engineering artifacts:** reusable `datasets-core` and `datasets-crawler` crates implementing visitors, scientific labelers, repository crawling, indexing, and query.
3. **Research resource:** an evidence-backed index of datasets encountered during evaluation, including their detected scientific contents and source information.

### Evaluation

| Evaluation | Measurement | Evidence of success | Failure signal |
| --- | --- | --- | --- |
| **Label accuracy** | Precision, recall, F1, and error analysis against manually verified examples | SMILES and formula labels correspond reliably to real dataset contents | Classification requires routine manual correction or produces substantial false positives/negatives |
| **Search quality** | Comparison with repository-native search on fixed queries/examples | Content-derived search identifies valid datasets that metadata search misses or ambiguously describes | Native repository search already provides equivalent verified discovery at much lower complexity |
| **Generalization** | Changes required to add the second repository, visitor, and labeler | Hugging Face/Zenodo, tabular/JSON, and SMILES/formula implementations fit the same core abstractions | Each new implementation requires redesigning the core |
| **Robustness** | Failures, malformed inputs, network errors, and fuzzing | Bad datasets fail locally without terminating or corrupting the crawl | Individual malformed resources repeatedly destabilize crawler runs |
| **Inspection cost** | Bytes inspected, requests, runtime, memory, and datasets processed | Useful labels can be established through bounded inspection for a meaningful fraction of candidates | Reliable classification normally requires completely downloading and parsing very large datasets |
| **Interoperable access** *(later phase)* | Correct extraction of shared validated fields while retaining source identity | Differently structured datasets can expose the same requested scientific content through one API | Typed access still requires dataset-specific downstream extraction code |

A negative result remains useful. If content-aware labeling does not improve on repository-native discovery, requires prohibitively expensive inspection, or repeatedly collapses into repository-specific logic, the project will establish practical limits on this approach.

### Closest Comparative Projects

**Hugging Face** is the most immediate comparator because it is both an MVP source and an existing dataset-search environment. The project therefore cannot claim novelty simply from making Hugging Face searchable. The test is whether inspection and validation of actual values provides more reliable scientific content classification than existing metadata, full-text search, schemas, or generated Croissant information.

**Google Dataset Search** is the closest architectural precedent for cross-repository crawling and indexing. Its work also demonstrates that repository metadata can be noisy. `datasets-rs` narrows the initial problem by using domain validators to determine whether particular scientific objects actually occur inside artifacts and by retaining field-level evidence for those labels.

**Croissant** is the closest general representation standard. The project should reuse Croissant metadata when available rather than designing another general dataset-description format. `datasets-rs` contributes a different layer: repository crawling, value-level scientific labeling, evidence-backed indexing, and potentially standardized typed access to fields discovered through those labels.

MetabolomicsHub is also important to the initial scientific use case. Rather than competing with its harmonized metabolomics portal, `datasets-rs` begins from generic repositories such as Hugging Face and Zenodo where relevant datasets may not already be known or consistently described.

## Technologies

The project will be implemented in Rust, using explicit typed representations for dataset metadata, acquisition sources, and locally materialized artifacts. Rust is consistent with the broader doctoral methodology of investigating reliable scientific infrastructure and enables validation of many invariants through the type system while retaining the performance required for large scientific resources.

Initial acquisition mechanisms will include ordinary HTTP downloads and repository/API clients such as Zenodo. Additional source adapters will be added only when required by datasets selected for evaluation. Format-specific interpretation should remain in appropriate downstream libraries where possible.

Internet access is required for public repositories and APIs. The initial dataset set should not require privileged authentication, dedicated external servers, or software deployment within Zenodo, Hugging Face, GNPS, or other providers. Rate limits and provider usage policies will be respected. If future work requires restricted or proprietary resources, authentication and access-control requirements will be treated as a separate extension rather than assumed by the initial design.
